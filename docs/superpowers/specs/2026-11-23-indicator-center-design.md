# 指标中心设计方案

- 版本：v1.0
- 日期：2026-11-23
- 关联：《2026-11-23-asset-catalog-platform-design.md》《客户与营销域数据模型打样_V2.md》《客户服务域数据模型打样_V1.md》
- 目标库表：`dim_indicator`（53 项）、`dim_caliber_dict`（38 条）

---

## 1. 背景与问题

现有指标与口径数据由 AI 起草、脚本落库，没有维护界面，也没有校验约束：来源字段可能已不存在、公式可能是自然语言、编码可能重复、口径可能冲突，出了问题无从发现。

指标中心不是"把两张表搬到界面"，而是建立 **导入 → 校验 → 人工修订 → 发布** 的受控流程。

## 2. 已确认决策

| 决策 | 结论 |
|---|---|
| 审批流 | 不做，仅"校验门禁 + 人工确认发布" |
| 存量导入 | 53 项指标 + 38 条口径全部导入为**草稿**，逐条修订后发布 |
| 指标与口径关系 | **一对一**：一个指标只关联一条口径；口径后续如需拆分会调整模型增加字段 |

## 3. 状态机

```text
AI 起草 / 导入 / 手工新建
        ↓
     草稿 DRAFT ──校验──▶ 有问题（阻断）──▶ 人工修订
        │                                   │
        └──────── 校验通过 ─────────────────┘
                    ↓
              已发布 PUBLISHED（可被资产/血缘引用）
                    ↓
              已废止 RETIRED（保留历史，不可引用）
```

规则：**存在阻断级问题时不允许发布**；已发布对象修改后自动回到草稿并重跑校验。

## 4. 数据模型（新增 4 张表）

### 4.1 `ast_indicator` 指标

| 字段 | 说明 |
|---|---|
| indicator_code | 指标编码，唯一，如 BM03008 / WO01009 |
| indicator_name | 名称，同域内唯一 |
| theme / domain_code | 分析主题 / 所属数据域 |
| indicator_level | 战略/管理/运营 |
| indicator_type | 原子/衍生 |
| indicator_def | 定义（文字） |
| formula | 口径公式（可解析表达式） |
| unit / cycle | 单位 / 累计周期（日/月/年） |
| source_asset_column_id | 来源字段，FK → `ast_asset_column.id` |
| carry_asset_column_id | 承载字段，FK → `ast_asset_column.id`（可空） |
| carry_type | 承载方式：DWS 固定列 / 明细现算 / 配置项 |
| caliber_id | 关联口径，FK → `ast_caliber.id`（一对一） |
| status | DRAFT / PUBLISHED / RETIRED |
| source_type | AI / HUMAN / IMPORT，记录起草来源 |
| owner_name | 责任人 |
| created_at / updated_at | |

### 4.2 `ast_caliber` 口径

| 字段 | 说明 |
|---|---|
| caliber_code | 唯一 |
| caliber_name | 名称 |
| caliber_def | 业务口径说明 |
| formula | 计算公式 |
| source_fields | 依赖字段（文本，校验时解析） |
| value_type | 标准 / 可配置 |
| apply_layer | DWD / DWS |
| status | DRAFT / PUBLISHED / RETIRED |
| source_type / owner_name | 同指标 |

### 4.3 `ast_governance_rule` 校验规则

rule_code、rule_name、target（INDICATOR/CALIBER）、severity（BLOCK/WARN）、params（JSON）、enabled、description。

规则由平台内置初始化，可在"指标中心 → 规则"查看与开关，新增规则不改代码。

### 4.4 `ast_indicator_version` 变更历史

object_type（INDICATOR/CALIBER）、object_id、version_no、changed_by、changed_at、changes（JSON：字段、改前、改后）、comment。

## 5. 校验规则（首批 10 条）

| 编码 | 规则 | 级别 |
|---|---|---|
| R01 | 必填字段完整（编码/名称/定义/公式/单位/周期） | 阻断 |
| R02 | 编码唯一且符合主题码规范 | 阻断 |
| R03 | 来源字段已挂到已登记资产字段 | 阻断 |
| R04 | 承载字段存在且为数值型 | 阻断 |
| R05 | 公式可解析，不能是纯自然语言 | 阻断 |
| R06 | 必须关联口径 | 警告 |
| R07 | 同域内名称不重复 | 警告 |
| R08 | 暂缓/跨域指标不得挂承载字段 | 警告 |
| R09 | 单位/周期与指标类型匹配（比率 %、金额 元） | 警告 |
| R10 | 已发布指标必须有责任人 | 警告 |

校验实时执行（规模小），结果写入对象最近一次校验快照（状态 + 问题列表），列表页直接展示。

## 6. 导入流程

1. 选择目标库中的 `dim_indicator` / `dim_caliber_dict`（数据源已配置）；
2. 预览前 20 行，确认字段映射；
3. 导入为草稿：`source_type = IMPORT`；
4. 自动解析 `source_table_field`（形如 `表.字段`）→ 资产字段，解析失败进入"待挂载"清单；
5. 跑校验，生成问题报告；
6. 人工逐条修订 → 发布。

**不自动发布**，避免把 AI 生成的问题固化。

## 7. 界面

| 页面 | 内容 |
|---|---|
| 指标中心 | 列表（编码/名称/状态/校验结果/来源/承载/口径）+ 筛选 + 新建 + 导入 |
| 指标详情 | 表单（来源/承载字段用字段选择器，不允许手填）、校验面板、变更历史、引用情况 |
| 口径管理 | 列表、关联指标（一对一反向查询）、编辑 |
| 导入向导 | 预览、字段映射、导入结果、待挂载清单 |
| 规则管理 | 规则列表、开关、严重级别 |

## 8. 防"随意维护"的硬约束

1. 所有变更走 API + 界面，不允许直接写库（界面外操作不在保障范围）；
2. 发布前必须通过阻断级校验；
3. 已发布对象修改 → 退回草稿重审；
4. 来源字段/承载字段只能从资产字段中选择，杜绝悬空引用；
5. 每次修改写版本记录，可追溯"谁在什么时候把公式从 A 改成 B"；
6. AI 起草对象标记 `source_type=AI`，发布时提示"AI 起草，待人工确认"。

## 9. 分期

| 阶段 | 内容 |
|---|---|
| I1 | 指标/口径主数据 + 导入向导 + 校验规则 + 列表/详情 |
| I2 | 发布门禁 + 版本历史 + 待挂载清单 + 规则管理页 |
| I3 | 引用影响分析（指标被哪些资产/血缘引用）、指标健康度巡检 |
